# Desktop (Electron)

This package hosts the shared React frontend as a macOS Electron application. It does not own a frontend source tree and does not launch or bundle the backend.

## Prerequisites

- macOS with Xcode Command Line Tools installed (`xcode-select --install` if needed).
- Node.js `22.19.x` LTS and npm. The repository pins this in [`.nvmrc`](.nvmrc) and declares it in `package.json`; Node 26 is not a supported build environment for this Forge project.
- A separately installed and already-running backend.
- A production frontend build generated by the build command.

## Configure the backend

On macOS this is typically:

```text
~/Library/Application Support/RSI Agent/desktop.json
```

The exact path is displayed in the configuration error if the file is missing. Create it with:

```json
{
  "backendOrigin": "http://127.0.0.1:3100"
}
```

The value must be an absolute HTTP/HTTPS origin without a path, query, fragment or credentials. The Desktop app never guesses this value and never starts or stops the backend.

## Development

From this directory, use a clean install under the pinned Node LTS version:

```sh
nvm install
nvm use
xcode-select --install  # only if the Command Line Tools are not installed
npm ci
npm run build
npm start
```

`npm ci` is the standard install step: it downloads the Electron runtime and compiles the host-platform native dependencies used by the DMG maker. Forge then uses its normal native-module rebuild lifecycle during packaging. Do not copy Electron binaries, create `path.txt` manually, or extract cached ZIPs by hand.

`npm start` builds `frontend/` first, copies only `frontend/dist` into the packaging staging directory, compiles the Electron host, and starts Forge. The Electron host has no React source of its own.

If `npm start` reports `node: --use-env-proxy is not allowed in NODE_OPTIONS`, your shell startup file is adding a Node 26-only option globally. This project uses Node 22.19.x, so remove that export from `~/.zshrc` (or make it conditional by Node version), reload the shell, and retry:

```sh
unset NODE_OPTIONS
nvm use
npm start
```

The project does not set `NODE_OPTIONS`; do not add `--use-env-proxy` to the Desktop scripts.

## macOS package

On macOS, the standard packaging command is:

```sh
nvm use
npm run make:mac
```

This builds the shared frontend, packages the arm64 Electron app, and invokes the configured ZIP and DMG makers. The DMG maker is macOS-only. The first creates a packaged app; the second creates macOS ZIP/DMG artifacts. Signing and notarization are not configured yet.

## Boundaries

- `src/main`: Electron lifecycle, secure custom protocol, backend-origin config and HTTP/SSE forwarding.
- `src/main/preload.ts`: only the typed API-base capability.
- `frontend/`: shared React source and `BackendClient`; browser behavior remains independent.
- Backend process, Agent execution, workspace files and Bash remain outside Desktop ownership.
