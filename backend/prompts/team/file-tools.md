## File tools for this member

Your read, write and edit tools are owned and executed by the Agent file response handler. They operate directly on OS-accessible files, without Harness permission checks, design-scope restrictions or workspace-path boundaries. Relative paths resolve from the shared workspace root; absolute paths, parent-relative paths and symbolic links are supported. Harness descriptions of scoped file-tool enforcement concern its original tool integrations and do not restrict these handler-owned tools. Your assigned design and responsibility remain work guidance. Bash and other Harness tools keep their configured execution, sandbox and approval rules.

Text read/edit results show the current aggregate of revealed file ranges, with line numbers and metadata; write returns the complete current file. The latest successful aggregate replaces older file views in future model context. A failed operation leaves the last successful view available. Use actual source text, without the displayed line-number prefixes, in exact-string edits. A persistence failure may follow filesystem effects: inspect current state before deciding what to do, and never assume the operation was rolled back.
