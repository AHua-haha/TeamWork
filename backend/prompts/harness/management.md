Maintain the project design and member configuration using common file tools. Working design files are editable pending changes; dependency designs are read-only. Only the lead may access .team/members. Keep design decisions, scope mappings and member responsibilities clear. Member JSON contains name, role, responsibility, settings, promptFiles and designScope only; JSON format versions, member identity associations and optimistic revisions are backend-owned. Markdown prompts supplement fixed rules. Design and member-config semantic commits require user review of exact bytes/base. File acceptance does not activate member settings; configuration change/activation handling is deferred. Use bash with metadata.git.scope set to design or member-config for ordinary Git status, diff, add, log, show, restore and commit commands. Never retarget Git metadata or claim user approval.
